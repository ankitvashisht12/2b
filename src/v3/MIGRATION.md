# V3 migration

`migrateVaults({root, sources?, dryRun?, inventoryPath?})` imports through `ObjectStore`. The caller chooses the destination path. The default source paths are `~/obsidian/2bv2` and `~/obsidian/personal`. Source trees and destination must not overlap. Both real source vaults remain protected even when test sources are supplied.

Do not run the real import until the parent implementation is ready. Start with `dryRun: true`. This hashes all retained files and reports totals, skipped paths, and unresolved links. It does not open the store, write app configuration, or create destination files. Agent defaults are read from `TWOB_APP_HOME/config.json` or `~/.2b/config.json`; reading missing configuration does not create it.

Every retained file gets a byte-exact, content-addressed archive copy. Each path includes its SHA-256 content hash. A changed source creates a new version and keeps the old bytes. The object ID still depends on the source path, not the content hash. Archive paths start with `archive/legacy` or `archive/personal`. This includes unregistered content, rules, logs, run history, and configuration. `.git`, `.obsidian`, `.DS_Store`, `node_modules`, `__pycache__`, `.cache`, and `.Trash` are excluded. Symlinks and special files are reported and skipped. Existing destination symlinks cause an error. Archive path components escape `%` and `.2b` to prevent collisions and nested live vault detection. `archivePath` and the path map give the exact destination path.

File object IDs depend on source vault and original path. Native project, task, collection, and note readme records keep their structure. Notes expose `noteType`, including meeting and journal. Unsupported note types remain in `sourceNoteType`. Native links, PRs, resources, artifacts, output, repository, branch, and recurrence fields are exposed as properties. Semantic frontmatter and known automation configuration are bounded to 64 KB before parsing. Generic JSON is archived without copying its parsed contents into the database. Large individual metadata fields remain in the archive and are named in `archivedFields`. No full file body is stored in the database. A database object is capped at 128 KB. Local references also create typed graph edges. Directory membership and explicit project or collection membership are retained. Unknown flat YAML syntax remains in `unparsedFrontmatter` and the original archive.

An artifact object's `path` points to its actual archived file. Registered Markdown artifacts also use this rule. `indexPath` points to an optional small index page. Artifact index pages do not repeat the full artifact body. Other readable pages use meaningful titles and stable ID suffixes. Daily appraisal names include the full date and source context.

Work planning is an ongoing project with four standard collections: quarterly goals, daily updates, weekly reports, and release posts. Native planning fronts are archived with their metadata intact. Task records join the relevant collection; their historical logs and artifacts keep their original parent links.

The prior inventory CSV supplies project and collection guidance. Set `inventoryPath` to use a different inventory. The default is the planning CSV provided for this task. Collection identity includes both project and collection. This prevents two unrelated collections called planning from merging. Inventory guidance first resolves an existing native legacy project at `projects/<project>/readme.md`. Projects such as travel, home, personal content, and Tars content are created only if the native project is absent. The inventory `kind` controls whether a personal source file is a note, artifact, project, task, or collection. Medium and review suggestions have a pending grouping marker. HOLD and EXCLUDE never delete content. Work planning inventory rows join the same generated planning project and standard collections.

Objects get work or personal context tags, source project topics, inventory topics, and explicit source tags. Source project area takes precedence over the source vault default. Tag objects have `path: null` and no generated page. Tag context stays in object properties. No per-file `tagged-with` edge is created, which avoids a graph hub for every work or personal file.

Entity creation uses source evidence. Explicit person, book, organization, and system types are retained. Named attendee or participant lists create people and attendance edges with the quoted list as evidence. Exact Book or System headings create linked objects. Exact $100M Offers, $100M Leads, and $100M Money Models titles, and explicit descriptions of a book called Manifest, create book nodes with text excerpts. Repository properties identifying Tars code create a Tars organization and the named system. An unambiguous short attendee name can resolve to a unique full name found in source evidence. The canonical person keeps the short name as an alias, with provenance. Ambiguous short names stay separate. No author, role, employer, edition, or biography is guessed.

Explicit source `created` and `modified` values take precedence over filesystem estimates. Zone-free source timestamps use Asia/Kolkata. Filesystem birth and modification times remain in separate source fields. Provenance states whether a timestamp came from metadata or the filesystem. `contentDate` uses a valid explicit date, the file’s own ISO date, or a `YYYY-MM/DD.md` daily path. A dated parent task directory is saved as `containerDate` and does not override a transcript filename. Binary files and source code do not acquire a content date from a task directory. Retrospective appraisal dates therefore stay separate from import and filesystem dates. Unknown completion dates remain unknown.

Native `kind: recurring` records become `agent-job` objects. EVERY, RUN, AGENT, and MODEL are read without regard to key case. Schedule-bearing records and imported jobs or reminders have `enabled: false` and `migrationReview: pending`. Original configuration is retained. An absent agent or model can use the configured primary or matching fallback agent choice, with configuration provenance. No command is executed and no scheduler or OS job is registered.

Local Markdown links and native wiki links first resolve within the source vault. Relative sibling-vault links such as `../personal/` and `../2b/` resolve by their actual source paths. A wiki alias can resolve across vaults only when no local match exists and the cross-vault match is unique. Absolute source links can resolve across the two vaults. Generated links point into the destination and retain heading fragments. Generated views strip source frontmatter and use one title heading. Destination `.obsidian/app.json` ignores `archive/`, `migration/`, and `.2b`; no source Obsidian setting is changed. Ambiguous or missing links remain unchanged and appear in the report. External URLs remain in source properties and readable text.

The migration writes a before checksum manifest, copies files, and checks each archive checksum. It scans and hashes the retained source set again after import. If a source changes while copying or verifying, the migration returns `complete: false`, `retryable: true`, and an error list. Bytes copied during a change are preserved under their actual hash. Metadata is not imported until the copied snapshot passes source verification. A later retry can finish without deleting old archive versions. A final source change also marks the report incomplete. A successful run writes the after manifest and path map under `migration/<manifest-hash>`. Excluded paths are reported separately.

Retries accept identical files and stable IDs. V3 semantic edits are preserved. Each import saves a source semantic baseline. An unchanged source retains the current V3 name, type, description, tags, status, and other semantic properties. A changed source updates fields that still match their prior imported values. User-edited fields remain intact and are listed in `metadataConflicts`. The source hash and provenance still advance. Changed automation sources are disabled pending review. New or changed canonical objects are written through `upsertMany`. Existing `createdAt` values remain immutable. Both object and relationship batches are limited by encoded bytes, with a 480 KB target and room below the 512 KB request limit. Relationships use deterministic IDs compatible with `ObjectStore.relate` and are written through `upsertRelationships`. Lookup maps and a relationship ID set avoid repeated graph scans. A corrupt content-addressed archive still causes an error. Generated pages have a saved generated-body hash. An unchanged generated page can update safely; its old version is kept in page history. A user-edited page stays intact. The proposed generated version is saved separately with `migrationConflict`, `userCopyPath`, and `generatedVersionPath`. Conflicts are listed in the report. Each report also retains the complete unresolved-link list. Keep sources and destination free of concurrent writers during import when possible.

Tests use temporary source and destination roots. `TWOB_APP_HOME` points to a separate temporary app home. Each fixture stops its SurrealDB process before removing its files. Default fixture tests do not use the actual source vaults or home configuration.

```
node --experimental-strip-types --no-warnings --test test/v3-migrate.test.ts
```

The full-scale test is opt-in. It reads the two real source vaults, imports twice into a temporary destination, uses a temporary app home, checks source manifests, and stops its database before cleanup. It never opens `~/obsidian/2b`. The proof JSON retains every unresolved link and each run’s byte limits, counts, and time.

```
TWOB_FULL_MIGRATION_PROOF=1 TWOB_MIGRATION_PROOF_PATH=/tmp/2b-v3-full-migration-proof.json node --experimental-strip-types --no-warnings --test --test-name-pattern='full-scale read-only source proof' test/v3-migrate.test.ts
```

V2 schedules are never unloaded or changed. No source configuration or OS job is touched. Automation-path detection is limited to native Markdown/JSON/YAML configuration paths. A file such as `tasks/.../fixtures/jobs/runner.ts` stays an artifact and does not become a schedule.
