# V3 integration contract

The new v3 implementation is separate from the v2 modules. Root defaults to ~/obsidian/2b. Never write to ~/obsidian/2bv2 or ~/obsidian/personal. Main checkout and global 2b launcher stay intact.

ObjectRecord: { id:string, type:string, name:string, description:string, properties:Record<string,unknown>, tags:string[], path:string|null, createdAt:string, modifiedAt:string }. Paths are vault-relative; optional files remain ordinary content. IDs stable across rename. Imported original metadata preserved under properties.sourceMetadata plus sourcePath/sourceVault/sourceCreatedAt/sourceModifiedAt/contentDate/dateConfidence. Don't invent actual historical completion times.
Relationship: {id:string,from:string,to:string,kind:string,properties?:Record<string,unknown>}. TypeDefinition: {id:string,name:string,description:string,properties:PropertyDefinition[]}; PropertyDefinition: {key:string,type:'text'|'number'|'boolean'|'date'|'datetime'|'select'|'relation'|'json',required?:boolean,options?:string[],targetType?:string}.

Store module src/v3/store.ts exports ObjectStore with static async open(root:string):Promise<ObjectStore>, async list(filters?:{type?:string,search?:string,status?:string,tag?:string,limit?:number,offset?:number}):Promise<ObjectRecord[]>, get(ref):Promise<ObjectRecord|null>, upsert(record):Promise<ObjectRecord>, upsertMany(records):Promise<void>, update(id,patch):Promise<ObjectRecord>, relate(from,kind,to,properties?):Promise<Relationship>, relationships(id?:string):Promise<Relationship[]>, upsertRelationships(records):Promise<void>, types():Promise<TypeDefinition[]>, defineType(definition):Promise<TypeDefinition>, close():Promise<void>. No canonical JSON database fallback. SurrealDB actual metadata authority. Store may add helpers/exports. Agent owns store.ts, models.ts, db runtime, corresponding tests. Common types exported from models.ts.

Migration module src/v3/migrate.ts exports async migrateVaults({root,sources?:{personal:string,legacy:string},dryRun?:boolean}):Promise<report>. It uses ObjectStore, copies all actual user content (including unregistered task artifacts), excludes VCS/cache junk, creates meaningful filenames+Obsidian links in generated readable views, preserves byte-exact original content in source archive or canonical copies, source checksums before/after, resumable/idempotent import, source date provenance. Original source paths always read-only. Imported recurring tasks/reminders do NOT activate schedules: retain original state/config and migrationReview marker. Migration owns no outside source writes. Safe relative paths; no symlink following outside source.

Dashboard UI files dash-v3/{index.html,app.js,app.css}. Parent builds HTTP server. REST: GET /api/state -> {objects,relationships,types,stats,root}; GET /api/object?id= -> {object,relationships,body}; POST /api/objects body {type,name,description?,properties?,tags?,body?}; PATCH /api/objects/:id {name?,type?,description?,properties?,tags?,body?}; POST /api/relationships {from,kind,to}; POST /api/types type definition; GET /api/file?path= -> file bytes (safe confined vault); POST /api/reconcile -> report; GET /api/health -> {ok,version}. On errors JSON {error}. No fake data, no external services or content uploads. Defaults UI Today mixed feed, Inbox processingState, Objects filter by type, Projects, Collections, People, Books, Tags, graph, Types. Persist CRUD and source detail links. Dates use user's Asia/Kolkata timezone in UI. Never claim imported schedules are active. No execute arbitrary commands via UI.
